# Дизайн-система SEO-сайта — seojazz.ru

> Этап 05 конвейера вайб-кода. Забирает handoff: прототипы Г1–Г7, контент (`04-kontent`), UX-модель (`05-dizajn/ux-konversionnaya-model.md`), реестр кейсов (`kejsy.md`), реальный сайт seojazz.ru. Обновлено: 2026-07-09.

## 1. Входные данные
### Проект
seojazz.ru — сайт SEO-агентства (WordPress, тема `seojazz-new`). Матричный каталог из 240+ посадочных (услуга × CMS × тип × ниша × регион × площадка) + GEO/AI-кластер + создание сайтов + площадки. Аудитория B2B (владельцы бизнеса, маркетологи), РФ/Москва, Яндекс-first. Позиционирование: «платите за заявки и выручку, а не за позиции», «без сложной терминологии и отчётов».
### Использованные материалы
Прототипы Г1–Г7; контент-пакеты; UX-модель; реестр кейсов и трастовых цифр; живой сайт (структура меню, герой, тарифы, контакты, логотип, целевые действия).
### Загруженные / переданные референсы
| Референс | Что удалось проанализировать | Полезные идеи | Ограничения |
|---|---|---|---|
| seojazz.ru (главная, web_fetch) | Структура, герой «107 650 заявок», тарифы 5 ступеней с KPI/гарантией, меню, CTA «Получить рекомендации», телефон, TG, рейтинг Яндекс, лого `seojazz-logo.svg`, тема `seojazz-new` (WordPress) | Готовый оффер, тон без жаргона, тарифная логика, сигнатурный CTA, трастовый счётчик | Точные HEX-цвета и файлы шрифтов из CSS не считались (web_fetch отдаёт очищенный текст; браузер/curl не используем) |
| Логотип seojazz-logo.svg | Есть SVG-лого (масштабируемое) | Векторное лого — под ретину и любой размер | Содержимое SVG (фирменные цвета) не прочитано — на сверку |
### Ограничения
- **Точные фирменные цвета и шрифты — `[Нужно уточнить]`** (снять из CSS темы `seojazz-new` или брендбука). Ниже — палитра и типографика как `[гипотеза]` с обоснованием ролей.
- Логотип есть (SVG) — не переизобретаем.
- Тексты не пишем здесь (это `napolnenie-stranic`); UX-логику — `ux-konversionnaya-model`.

## 2. Краткий вывод
Дизайн-направление: **строгий экспертный технологичный минимализм с одним «джазовым» акцентом** — быстрый, масштабируемый на сотни посадочных, подчинённый SEO и конверсии. Ядро — библиотека переиспользуемых блоков (см. `master-shablon §7`), из которых конфигом собирается любая из 240+ страниц. Визуальный приоритет — оффер, трастовый счётчик «107 650 заявок», кейсы в деньгах и один заметный CTA. Красота вторична: не делаем тяжёлую витрину, держим Core Web Vitals и место под контентное расширение.

## 3. Визуальная концепция
### Основная идея
«SEO Jazz» — экспертиза, которая играет слаженно, как джаз-бэнд: строгая структура + человеческий, без канцелярита тон. Чистый корпоративный лейаут, много «воздуха», данные и цифры как главный визуальный герой (результаты в деньгах/заявках), один тёплый акцент как «джазовая нота» на CTA и ключевых метриках.
### Характер дизайна
| Параметр | Решение |
|---|---|
| Стиль | Экспертный, технологичный, деловой; минимализм с акцентами `[гипотеза]` |
| Эмоция | Уверенность, прозрачность, «эти ребята про результат, а не про отчёты» |
| Плотность контента | Средняя (посадочные длинные, но с «воздухом» и якорями) |
| Акценты | Цифры-метрики, кейсы А→B, счётчик заявок, CTA, GEO/AI-блок |
| Изображения | Реальные графики роста, скриншоты кейсов, фото команды/эксперта; минимум стоков |
| Иконки | Линейные, единый набор, тонкие; без пёстрых эмодзи в UI |

## 4. Цветовая система
> Значения — `[гипотеза]`, сверить/заменить точными из темы `seojazz-new`/брендбука. Логика ролей важнее конкретных HEX.

| Роль | Рекомендация | Где | Комментарий |
|---|---|---|---|
| Основной (бренд) | Глубокий сине-графитовый `#1B2A4A` `[гипотеза]` | Шапка, заголовки, футер | Экспертность, доверие, деловой тон |
| Дополнительный | Нейтральный серо-синий `#33415C` `[гипотеза]` | Подзаголовки, иконки, границы | Поддержка основного |
| Акцентный («джаз») | Тёплый янтарь/оранж `#F5A623` `[гипотеза]` | CTA, ключевые метрики, активные состояния | Единственный тёплый акцент — направляет к действию |
| Успех/рост | Зелёный `#2FB37A` `[гипотеза]` | Метрики роста «×N», галочки в тарифах | Для положительных цифр кейсов |
| Фон | Белый `#FFFFFF` + светлый `#F4F6FA` `[гипотеза]` | Чередование секций | «Воздух», читаемость |
| Текст | Почти чёрный `#1A1A1A` `[гипотеза]` | Основной текст | Контраст ≥ 4.5:1 |
| Второстепенный текст | Серый `#6B7280` `[гипотеза]` | Подписи, мета | Не для важного контента |

Требование: контраст текста и CTA — WCAG AA (≥4.5:1 для текста, ≥3:1 для крупного). Акцентный цвет — только для действий и ключевых чисел, не «раскрашивать» весь макет.

## 5. Типографика
> Семейства — `[гипотеза]`, сверить с темой. Рекомендация: один гротеск с кириллицей и хорошей читаемостью (напр. Golos Text / Manrope / Inter) для всего, второй — опционально для акцентных заголовков.

| Элемент | Рекомендация | SEO/UX-комментарий |
|---|---|---|
| H1 | 32–44px, bold, максимум 1 на страницу, текстовый | Главный SEO-заголовок, всегда текст (не картинка), виден на 1-м экране |
| H2 | 26–32px, semibold | Соответствует структуре блоков контента, не заменяется декором |
| H3 | 20–24px, semibold | Подразделы, FAQ-вопросы, карточки |
| Основной текст | 16–18px, line-height 1.6 | Читаемость на мобильном, не мельче 16px |
| Списки | 16–18px, маркер акцентным | Облегчают чтение длинных посадочных |
| Таблицы (тарифы/сравнение) | 14–16px, зебра | Адаптивны: на мобильном — карточки/аккордеон |
| FAQ | Вопрос H3/semibold, ответ 16px | Answer-first, раскрытие аккордеоном, разметка FAQPage |
| Цитаты/экспертные вставки | 18–20px, акцентная линия слева | Выделяют E-E-A-T и «подтверждено данными» |

## 6. Сетка и адаптивность
### Desktop
Контентная область 1200–1280px, 12-колоночная сетка, gutter 24–32px. Секции на всю ширину с внутренним контейнером; чередование фонов (белый/светлый).
### Tablet
8 колонок; карточки 2 в ряд; таблицы тарифов — горизонтальный скролл или 2+1; меню сворачивается в бургер на ≤1024px.
### Mobile
1 колонка; карточки в стек; таблицы → карточки/аккордеон; калькулятор и квиз — по шагу на экран; sticky нижняя панель (Позвонить/TG/Заявка).
### Важные адаптивные правила
1. Главный CTA виден на первом экране без скролла на всех устройствах.
2. Тяжёлые таблицы (тарифы, сравнение GEO) на мобильном — аккордеон/карточки, не горизонтальная простыня.
3. Точки перелома: 1280 / 1024 / 768 / 480. Ничего не «ломается» при добавлении контента.

## 12. Изображения, иконки, иллюстрации
### Изображения
Реальные графики роста из кейсов, скриншоты «до/после», фото команды и эксперта, фото объектов ниши. Формат webp, ленивая загрузка, фикс. размеры (без сдвигов CLS).
### Иконки
Единый линейный набор (SVG-спрайт), тонкие, в цвете основной/дополнительный; акцентный — только на действии.
### Иллюстрации
Умеренно — схемы «комплекс каналов», «путь пациента/клиента», воронка GEO. Не перегружать.
### Что нельзя
Пёстрые эмодзи в UI, дешёвые стоки «рукопожатие/лампочка», тяжёлые 3D/видео-фоны, скопированные решения конкурентов, важный текст «зашитый» в картинку.

## 13. Требования к скорости и реализуемости
Лёгкий hero (webp, без видео-фона); умеренная анимация (микровзаимодействия, не тяжёлые эффекты); переиспользуемые компоненты (одна библиотека на 240+ страниц); WordPress-тема `seojazz-new` — держать быстрой (кэш, критический CSS, отложенный JS); Core Web Vitals в зелёной зоне (важно для GEO/AI-цитируемости и ранжирования); добавление новой посадочной = новый конфиг блоков без правки вёрстки.

## 14. SEO-ограничения для дизайна
1. H1 текстовый и видимый, один на страницу. 2. H2–H3 соответствуют структуре контента, а не заменяются декором. 3. Важный SEO-текст (особенности ниши, FAQ, «что входит») — текстом, не в картинке. 4. Ключевые блоки не прячем так, что теряется смысл/индексация. 5. Внутренние ссылки матрицы — видимые, кликабельные, не только JS. 6. FAQ читаем, размечен FAQPage. 7. Таблицы тарифов/сравнения адаптивны и текстовые. 8. Карточки услуг/ниш/кейсов масштабируемы (сотни страниц). 9. Страница быстрая (CWV). 10. Макет допускает рост контента без поломки.

Собрать компоненты как переиспользуемую библиотеку; каждую страницу — из конфига блоков; формы с валидацией, согласием ПДн, отправкой в CRM `[уточнить]` и событиями аналитики (см. UX-JSON); адаптивные правила §6; держать CWV.
### Для SEO
H-структура не ломается; FAQ/таблицы/ссылки — текстовые и индексируемые; schema (Service/FAQPage/BreadcrumbList/Organization/LocalBusiness/AggregateRating); скорость.
### Для контента (`napolnenie-stranic`)
Ограничения по длине заголовков (H1 читаемый), объёму блоков, размеру таблиц; alt-тексты; тексты CTA/форм — по UX-модели.
