# Прототип страницы — Группа 4: SEO по CMS (движок)

> Эталонный прототип под страницу продвижения на конкретном движке. Размножается по 15 CMS (WordPress, Битрикс, Tilda, OpenCart, MODX, Joomla, Drupal, InSales, Magento, Webflow, Wix, Shop-Script, UMI, Битрикс24, самописные). Рабочий пример — `/seo-prodvizhenie-bitrix/`.
> Ключ: **весь контент — под технические особенности движка**. Вход — `02-bloki-analiz/gruppa-4-cms.md`.
> Обновлено: 2026-07-06.

- **Тип страницы:** посадочная услуги под движок
- **Интент:** коммерческий (Bitrix/OpenCart/MODX/Joomla/Drupal/Magento) / инфо (WordPress/Tilda — гибрид гайд+услуга)
- **Конверсионная цель:** заявка / расчёт через квиз
- **Первый экран:** «SEO для <CMS>» + 3 УТП под движок + CTA

---

## Структура блоков

### 1. Hero `[обязательный]`
- **Задача:** зацеп под движок.
- **Смысл:** H1 «SEO-продвижение сайта на <CMS>» + подзаголовок «чтобы особенности движка работали на трафик и заявки» + 3 УТП-плашки (SEO под структуру движка / техбаза+индексация / фокус на заявках).
- **SEO-задача:** ключ «продвижение на <CMS>» в H1/1-м абзаце.
- **Конв-задача:** CTA «Рассчитать стоимость».

### 2. Квиз-калькулятор `[обязательный, наш акцент]`
- **Задача:** вовлечь и квалифицировать.
- **Смысл:** 5–8 адаптивных вопросов (задача → этап сайта → URL → что продвигать → проблемы → формат/срок → контакты) → PDF-КП + консультация.
- **Функционал:** пошаговый квиз.

### 3. «С какими задачами приходят на <CMS>» `[обязательный]`
- **Задача:** показать понимание тех-специфики движка.
- **Смысл:** 6 CMS-проблем (мало трафика; сложная структура/дубли; индексация; скорость/модули; трафик есть — заявок нет) — на языке сущностей движка (Битрикс: инфоблоки/компоненты/ЧПУ; Drupal: Views/таксономии).

### 4. Кому подходит / не подойдёт `[обязательный]`
- **Смысл:** «подходит если есть доступ к разработке/структура/спрос» / «не начинать если нет доступа к шаблонам, хаос в структуре, нет спроса».

### 5. Что входит в SEO на <CMS> `[обязательный]`
- **Смысл:** аудит движка, семантика под структуру, настройка индексации/дублей, оптимизация под сущности CMS (инфоблоки/Views/шаблоны), метатеги+микроразметка, техническая оптимизация CMS.
- **SEO-задача:** тематическая полнота по движку.

### 6. Как строится работа (этапы) `[обязательный]`
- **Смысл:** 4 этапа: архитектура/техсостояние → семантика/распределение → SEO-логика+усиление страниц → анализ+масштабирование.

### 7. Прайс `[обязательный]`
- **Смысл:** 3 сценария — аудит от …₽ / под ключ от …₽ / сопровождение разработки от …₽. `[данные: суммы]`

### 8. Матрица перелинковки `[обязательный — SEO-приём]`
- **Задача:** внутренний линкинг между кластерами.
- **Смысл:** карточки «SEO по типу сайта / по нише / по другим CMS / по региону» с ценой «от».
- **Функционал:** сетка карточек.

### 9. Кейсы с метриками `[обязательный]`
- **Смысл:** карточки «SEO для <ниши на этом движке> — рост заявок/трафика ×N». `[данные: наши кейсы]`

### 10. Почему выбирают + счётчики `[обязательный]`
- **Смысл:** счётчики (проекты/отзывы/рост заявок), «смотрим маркетинг через заявки».

### 11. Сертификаты / членство `[желательный]`
- **Смысл:** партнёрство Битрикс/Яндекс, ARDA и т.п. `[данные]`

### 12. FAQ по <CMS> `[обязательный, answer-first]`
- **Смысл:** «можно ли эффективно продвигать на <CMS>», «почему сайт на <CMS> плохо растёт», «техника vs структура», цена, сроки.
- **Микроразметка:** FAQPage.

### 13. GEO/AI-блок `[обязательный — блок-обгон]`
- **Смысл:** «продвигаем сайт на <CMS> и в ответы нейросетей».

### 14. Формы + бриф `[обязательный]`
- **Смысл:** мультиканальная форма + пошаговый бриф-квалификатор.

> **Для WordPress/Tilda (инфо-выдача):** между hero и «что входит» добавить **экспертный гайд-блок** («как настроить SEO на <CMS>: пошагово») — гибрид гайд+услуга, чтобы конкурировать со статьями в топе.

## CTA по странице
- Основной: «Рассчитать стоимость SEO для <CMS>» (квиз).
- Вторичный: «Заказать SEO-аудит <CMS>».
- В футере: «Заполнить бриф».

## FAQ (смысл ответов)
1. Можно ли эффективно продвигать сайт на <CMS>? 2. Почему сайт на <CMS> плохо растёт? 3. Что важнее — техника или структура контента? 4. Сколько стоит? 5. Нужен ли доступ к разработке?

## Внутренние ссылки
- → другие CMS (`/seo-prodvizhenie-wordpress/` и т.п.), типы сайтов, ниши, регион.
- → `/seo-audit-sajta/`, `/geo-prodvizhenie/`, `/cases/`.

## Микроразметка
- `Service`, `FAQPage`, `BreadcrumbList`, `Organization`.

## Функциональные требования
- Пошаговый квиз-калькулятор, бриф (8 вопросов), сетка карточек перелинковки, карточки кейсов, FAQ-аккордеон, мультиканальные контакты.

## Данные от клиента
- Суммы (аудит/под ключ/сопровождение); наши кейсы по движкам/нишам; сертификаты/партнёрства; глубина тех-контента по каждому движку; формат для WordPress/Tilda (гайд+услуга).

## Как адаптировать под другие движки
- Меняются: название CMS, названия её сущностей (инфоблоки/Views/плагины/шаблоны), список тех-проблем, «что входит», FAQ. Каркас единый. Для WordPress/Tilda — гибрид гайд+услуга.
