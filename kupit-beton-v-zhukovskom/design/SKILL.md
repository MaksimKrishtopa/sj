## РАЗДЕЛ 3: ПРАВИЛА ВЕРСТКИ

1. **Mobile-first** — пишешь стили для мобильных, потом добавляешь media queries для десктопа.
2. **Не копируй референсы 1:1** — адаптируй визуальные принципы, не воспроизводи чужие сайты.
3. **Дизайн-токены** — все цвета, шрифты, отступы — через CSS-переменные. Никаких хардкодов. Пример: `var(--color-primary)`, `var(--font-heading)`, `var(--spacing-lg)`.
4. **Семантический HTML** — используй `<header>`, `<main>`, `<section>`, `<article>`, `<footer>`, `<nav>`, `<aside>`. Не злоупотребляй `<div>`.
5. **Accessibility** — у всех изображений атрибут `alt`. У кнопок — `aria-label` если иконка без текста. Контраст текста на фоне — минимум 4.5:1 по WCAG AA.
6. **Контентные заглушки** — всё что не определено клиентом помечай: `<!-- [КОНТЕНТ ОТ КЛИЕНТА: описание] -->` в HTML и соответствующим placeholder-блоком.
7. **Ассетные заглушки** — если ассет отсутствует: `<img src="placeholder.jpg" alt="[описание: 1600x900, фото производства]" width="1600" height="900">` + CSS для placeholder с правильными пропорциями.
8. **Все токены в variables.css** — первый файл который создаётся. Содержит все CSS-переменные.
9. **Компоненты как переиспользуемые блоки** — описания из components.md применяй консистентно на всех страницах.
10. **Никаких inline-стилей** — только классы и CSS-файлы. Исключение — критически важные динамические стили через JS.
11. **Телефон всегда кликабелен** — `<a href="tel:+74991117262">+7 (499) 111-72-62</a>`.
12. **CTA в каждой секции** — каждый блок заканчивается призывом к действию или ведёт к форме.
13. **Lazy loading** — у всех изображений ниже fold: `loading="lazy"`.
14. **WebP с fallback** — `<picture>` с WebP и JPEG внутри, если используешь оба формата.

## РАЗДЕЛ 4: АНАЛИЗ РЕФЕРЕНСОВ

Когда клиент даёт ссылки, скриншоты или описания референсов — создай файл `design/references-analysis.md` со следующей таблицей:

| Референс | URL | Тип | Что берём | Что не берём | Визуальные особенности | Риск копирования |
|---|---|---|---|---|---|---|

**Типы референсов:**
- `конкурент` — прямой конкурент в нише (бетонные заводы)
- `визуальный стиль` — сайт с похожим желаемым стилем (не из ниши)
- `UX-паттерн` — конкретный UX-элемент (форма, калькулятор, фильтры)
- `типографика` — понравился шрифт или работа с текстом
- `анимации` — понравились переходы, scroll-анимации

**Правила анализа:**
- Отделяй визуальные принципы от прямого копирования
- Описывай конкретно: «тёмный hero с крупной цифрой цены» вместо «красивый дизайн»
- Если референс — конкурент, особо внимательно: берём принципы, не вёрстку
- Для каждого элемента который берём — пиши как адаптируешь, а не копируешь

После таблицы — раздел «Синтез визуальной ДНК»:
- 5–7 принципов стиля которые вытекают из референсов
- Анти-стиль: что точно не делаем

## РАЗДЕЛ 6: СТРУКТУРА ВЫХОДНЫХ ФАЙЛОВ

### Вариант A: Многостраничный сайт (HTML + CSS)
```
/src/
  [slug].html              — HTML страницы
  css/
    variables.css          — все CSS-переменные (первый файл)
    reset.css              — сброс стилей
    layout.css             — сетка и контейнеры
    typography.css         — шрифты и текстовые стили
    components.css         — переиспользуемые компоненты
    [slug].css             — стили конкретной страницы
  js/
    main.js                — общая логика
    calculator.js          — калькулятор (если нужен)
    forms.js               — обработка форм
  assets/ → ссылка на папку /assets/ проекта
```

### Вариант B: Единый лендинг (один файл)
```
[slug].html   — всё в одном файле: HTML + <style> + <script>
```
Используй этот вариант только если явно попросили «единый файл» или «лендинг для A/B теста».

### Вариант C: React / Next.js
```
/src/
  components/
    Header.tsx
    Footer.tsx
    [ComponentName].tsx
  pages/
    index.tsx
    [slug].tsx
  styles/
    variables.css
    globals.css
    [component].module.css
```

Стек определяется из design-brief.md раздел «Стек вёрстки». Если не указан — используй HTML+CSS (Вариант A).
