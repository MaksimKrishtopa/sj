# Дизайн-система SEO-сайта — «Вагон дом 2.0»

> Основа: структура, прототипы (`05_`), контент (`06_`), UX-модель (`07_`). Брендбук, логотип, фирменные цвета НЕ переданы — цвет и типографика даны как **[гипотеза]** с обоснованием роли; заменяются брендбуком заказчика. Референсы не передавались.

## 1. Входные данные
### Проект
Завод вагон-домов и модульных зданий (новый филиал). Сайт масштабный (≈1250+ страниц: категории, спец-типы, карточки, услуги, региональная матрица, блог). Дизайн подчинён SEO, контенту и конверсии.
### Использованные материалы
Структура сайта + URL, прототипы 11 типов, контент-пакет (мета/блоки), UX-модель (CTA/формы/доверие/мобайл).
### Переданные референсы
| Референс | Анализ | Идеи | Ограничения |
|---|---|---|---|
| — | Референсы/мудборды не передавались | — | Направление задаём гипотезой; согласовать с заказчиком |
### Ограничения
Нет брендбука, логотипа, фирменных цветов, шрифтов, фото/видео производства. Всё визуальное — гипотеза до брендбука. Не выдумываем бренд.

## 2. Краткий вывод
Концепция — **«завод-производитель: надёжно, технично, без витринного глянца»**. Система строится вокруг: быстрый первый экран с оффером+ценой+CTA, масштабируемые карточки (типы/модели/города), читаемые таблицы характеристик, заметные формы и sticky-CTA на мобильном, блоки доверия (кейсы, логотипы, сертификаты). Палитра `[гипотеза]`: спокойный «промышленный» синий (доверие) + один яркий тёплый акцент только под CTA + нейтральные серые. Главный принцип — **один переиспользуемый набор компонентов** на сотни страниц, лёгкий и быстрый.

## 3. Визуальная концепция
### Основная идея
Промышленный, «инженерный» стиль: чёткая сетка, крупная типографика, много воздуха вокруг оффера и CTA, фото реальной продукции/производства вместо стоков. Дизайн «работает», а не украшает: помогает выбрать тип → модель → оставить заявку.
### Характер дизайна
| Параметр | Решение |
|---|---|
| Стиль | строгий, экспертный, технологичный (без премиум-глянца) |
| Эмоция | надёжность, масштаб производства, спокойная уверенность |
| Плотность контента | средняя (высокая на каталоге/характеристиках, низкая на первом экране) |
| Акценты | цена «от», CTA, цифры-доказательства, фото объектов |
| Изображения | реальные фото продукции, объектов, производства `[Нужно уточнить: ассеты]` |
| Иконки | линейные, единый набор, простые (назначения/преимущества) |

## 4. Цветовая система `[гипотеза]`
| Роль | Рекомендация | Где | Комментарий |
|---|---|---|---|
| Основной | глубокий синий (#1F3A5F ≈) | шапка, заголовки-акценты, футер | доверие/промышленность; заменить фирменным |
| Дополнительный | сталь-серый (#4A5568 ≈) | подложки блоков, иконки | нейтральная опора |
| Акцентный | тёплый оранжевый/янтарный (#E8842A ≈) | ТОЛЬКО CTA, цена, важные метки | высокий контраст = заметный CTA; один акцент |
| Фон | белый + очень светлый серый (#F5F7FA) | чередование секций | ритм без пестроты |
| Текст | почти чёрный (#1A202C) | body/заголовки | читаемость, контраст AA |
| Второстепенный текст | серый (#718096) | подписи, мета | иерархия |
Правила: 1 акцент под действие (не красить всё), контраст текста ≥ WCAG AA, статусные цвета (успех/ошибка форм) — отдельно. Финальные HEX — из брендбука.

## 5. Типографика `[гипотеза]`
| Элемент | Рекомендация | SEO/UX-комментарий |
|---|---|---|
| Шрифт | гротеск с кириллицей (напр. Inter/Manrope/PT Root) | вебшрифт с сабсетом, 2 начертания — скорость |
| H1 | 32–40px/700, видимый текст | один на страницу, не картинкой |
| H2 | 24–28px/700 | секции = структура контента |
| H3 | 18–20px/600 | подкатегории/варианты |
| Body | 16–18px/400, межстрочный 1.5 | читаемость на длинных страницах |
| Списки | маркеры/чекмарки, отступы | облегчают чтение состава/комплектаций |
| Таблицы | 14–16px, зебра, адаптив | характеристики — не перегружать |
| FAQ | аккордеон, вопрос 16–18px/600 | читаемо + FAQPage |
| Цитаты/экспертное | выделенный блок, крупнее | усиление доверия/кейсов |

## 6. Сетка и адаптивность
### Desktop
Контентная область 1200–1280px, 12-колоночная сетка, gutter 24px. Карточки — 3–4 в ряд.
### Tablet
2–3 карточки в ряд; таблицы — горизонтальный скролл; sticky-хедер сохраняется.
### Mobile
1 колонка; первый экран: оффер+цена+CTA без скролла; нижняя sticky-панель (звонок/заявка/мессенджер/расчёт); карточки в 1–2 колонки; таблицы — «карточками»/скролл.
### Важные адаптивные правила
1. CTA и цена «от» всегда видны на первом экране (все брейкпоинты).
2. Таблицы характеристик не ломают вёрстку — адаптив/скролл, не картинкой.
3. Карточки — единый компонент, переиспользуемый для типов/моделей/городов.
4. Никаких горизонтальных «поехавших» блоков на мобильном.

## 10. Навигация
Главное меню: направления (Вагон-дома, Модульные здания, Вахтовые посёлки, Бытовки, В наличии) + О компании/Кейсы/Контакты; мега-меню с типами для «Вагон-дома»/«Модульные». Мобильное — бургер + нижняя sticky-панель действий. Хлебные крошки на всех вложенных. Внутренние ссылки: блоки «смежные типы», «в вашем городе», «наши работы» — видимыми ссылками. Sticky-хедер с телефоном/CTA. Футер — расширенная карта разделов (перелинковка) + реквизиты.

## 11. Формы, CTA и конверсионные элементы
| Элемент | Где | Визуальная логика | UX | Разработка |
|---|---|---|---|---|
| Основная кнопка | hero, формы, CTA-блоки | акцентный цвет, крупная, тень минимальная | 1 главная на экран | состояния hover/active/disabled/loading |
| Вторичная кнопка | рядом с основной | контурная/нейтральная | не конкурирует с основной | те же состояния |
| Форма заявки | финал, карточки, услуги | контраст-подложка, 1–2 поля+согласие | минимум полей | валидация, антиспам, согласие ПДн |
| Калькулятор | категории/услуги | пошаговый, прогресс | понятные шаги | компонент с логикой `[уточнить]` |
| Кнопка звонка | шапка + sticky моб. | заметная, номер | click-to-call | tel: ссылка |
| Мессенджеры | плавающая/панель | не перекрывать CTA | быстрый контакт | deep-links `[уточнить]` |

## 12. Изображения, иконки, иллюстрации
### Изображения
Реальные фото продукции, реализованных объектов, производства/цеха; для регионов — по возможности локальные. `[Нужно уточнить: фотобанк заказчика]`. До получения — аккуратные плейсхолдеры, не стоки.
### Иконки
Единый линейный набор (назначения, преимущества, этапы). Один стиль/толщина.
### Иллюстрации
Минимум; при нехватке фото — схемы/планировки (полезны на карточках).
### Что нельзя
Глянцевые стоки «менеджеры с касками», чужие фото/логотипы конкурентов, тяжёлые 3D/анимации, пёстрые градиенты, дизайн, который нельзя размножить на сотни страниц.

## 13. Скорость и техническая реализуемость
Лёгкие оптимизированные изображения (WebP, lazy-load), 1 вебшрифт (2 начертания, сабсет), умеренная анимация (без параллаксов на входе), переиспользуемые компоненты, компонентная сетка. Карточки/таблицы/hero — одни и те же шаблоны на всех страницах (быстрая генерация 1250+ страниц). Приоритет — Core Web Vitals (LCP на hero, CLS у форм/картинок).

## 14. SEO-ограничения для дизайна
1. H1 текстовый и видимый (не в картинке). 2. H2-H3 = структура контента, не декор. 3. SEO-текст и цены — текстом, не изображением. 4. Блоки доверия/FAQ/характеристики — в DOM, не за скриптом. 5. Внутренние ссылки видимые. 6. FAQ читаемо (аккордеон, но текст в разметке). 7. Таблицы адаптивны, не картинкой. 8. Карточки масштабируемы. 9. Страница быстрая. 10. Макет допускает рост контента (SEO-текст внизу, доп. блоки) без поломки.

## 15. Что передать следующим скиллам
### Дизайнеру (Figma)
Токены (цвет/шрифт/сетка), 8 шаблонов (§7), библиотека компонентов (§9) с состояниями, мобильные версии, первый экран каждого типа.
### Разработчику
Компоненты как переиспользуемые модули; состояния кнопок/форм; адаптивные правила; sticky-панель; калькулятор; галерея кейсов с фильтром; гео-подстановка города; lazy-load; согласие ПДн.
### SEO
Проверить H-иерархию по шаблонам, видимость ссылок/FAQ/текста, адаптив таблиц, скорость, отсутствие текста-в-картинках.
### Контенту
Ограничения: длина оффера (1 строка), Description 130–160, таблицы — компактные, alt на всех фото, блоки не «распухают».
### Вайб-кодингу
Собрать дизайн-систему как компоненты: `Hero`, `Card`, `DirectionTiles`, `SpecTable`, `Calculator`, `Timeline`, `CasesSlider`, `LogoStrip`, `FAQAccordion`, `LeadForm`, `CTABlock`, `StickyMobileBar`, `Breadcrumbs`; 8 шаблонов страниц; токены из JSON ниже.

## 16. Что должен проверить человек
Соответствие фирменному стилю (когда будет брендбук); не пустой ли дизайн; H-структура; масштабируемость шаблонов; скорость; мобильные CTA; достаточно ли доверия; конфликт дизайн↔SEO; отсутствие копирования конкурентов; наличие реальных фото/ассетов.

## 17. Итоговые требования к дизайн-системе
1. Единый набор переиспользуемых компонентов и 8 шаблонов на все ≈1250+ страниц.
2. Первый экран каждого типа: оффер + цена «от» + заметный CTA; на мобильном — sticky-панель действий.
3. Один акцентный цвет строго под действие/цену; палитра/шрифт — из брендбука (сейчас гипотеза).
4. Все SEO-ограничения соблюдены (текстовый H1, адаптивные таблицы, видимые ссылки/FAQ).
5. Лёгкость и скорость (WebP, lazy-load, 1 шрифт, минимум анимаций) — под Core Web Vitals.
6. Реальные фото продукции/объектов/производства; никаких стоков и копирования конкурентов.
