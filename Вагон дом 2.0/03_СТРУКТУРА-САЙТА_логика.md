# Структура сайта «Вагон дом 2.0» — рабочая версия (v4, гранулярная, суперсет)

**Статус: принята как рабочая структура сайта.** Открытые уточнения (бренд/контакты, финальный профиль производства, аренда/trade-in) не блокируют структуру — правятся при вводных заказчика.

Файлы:
- `СТРУКТУРА-САЙТА_Вагон-дом-2.0.xlsx` — Дерево (399 узлов), Аналитическая таблица, Инфо-страницы, Региональные, Дорожная карта, **+ вкладки «Матрица — список» и «Матрица — сетка»** (город × услуга).
- `СТРУКТУРА-САЙТА_Вагон-дом-2.0.xmind` — mind-map.
- `Матрица_город-услуга_Вагон-дом-2.0.xlsx` — отдельный файл: **20 услуг × 39 городов = 780 страниц** с готовыми URL (для кодинга/генерации).

## Главное изменение: каждое назначение — отдельная посадочная
Раньше я группировал. Теперь каждый тип помещения = свой URL/страница (люди ищут «вагон-дом кухня», «вагон-дом штаб», «вагон-дом раздевалка» по отдельности). Разведено:

- **Питание:** Столовая ≠ Кухня ≠ Комната приёма пищи ≠ Пекарня.
- **Гигиена:** Душевая ≠ Санузел (туалет) ≠ Баня ≠ Сауна ≠ Раздевалка ≠ Сушилка ≠ Прачечная ≠ Банно-прачечный комплекс.
- **Производственно-технические:** Слесарная мастерская ≠ Инструментальная мастерская ≠ Сварочный пост ≠ Мастерская (ремонтная) ≠ Операторская ≠ Лаборатория ≠ Станция водоподготовки.
- **Административные:** Офис ≠ Прорабская ≠ Кабинет руководителя ≠ Конференц-зал ≠ Штаб строительства ≠ Комната отдыха.
- **Медицина:** Медпункт ≠ Медпункт с изолятором ≠ Амбулатория ≠ ФАП.
- **Безопасность:** Пост охраны / КПП (с турникетом / с проживанием / Face ID).
- **Хранение:** Склад ≠ Продуктовый склад ≠ Морозильный склад.

Все **68 реальных моделей** сайта прикреплены листьями к своим типам (напр. столовые №701–707 под «Столовая», медпункты №1301–1305 под «Медпункт»). Типы, которые пока только в кейсах или у конкурентов (штаб, прорабская, раздевалка, операторская, амбулатория, ФАП, комната отдыха), заведены как «создать».

## Жилые — по-прежнему многослойно
Вместимость (1-2 / 2-4 / 4-8 / 8 / 12) × комплектация (с кухней, с санузлом, с печью, с душевой, с обеденной зоной, с тамбуром, с сушилкой, с комнатой отдыха) × исполнение (повышенной комфортности, ВИП, «серый камень») + модели.

## Где масштаб
Мультипликация фасетов: **назначение × вместимость × комплектация × конструкция × регион**. ~40 назначений уже дают широкий коммерческий слой; регион его умножает.

## Не изменилось
Сохраняем все 269; разнобой юрлиц убираем; 155 кейсов систематизируем и перелинковываем; «на колёсах» — синоним в Title «на шасси»; спорные (P4) — быстровозводимые/металлоконструкции/ангары только по решению заказчика. Региональную матрицу разворачиваем управляемо (сначала хабы, потом назначение×город по спросу и логистике), чтобы не плодить тонкие страницы.

## Уточнения к заказчику
Бренд/контакты; города и география (размер матрицы); профиль (модульные/быстровозводимые — да/нет); аренда/trade-in; приоритетные маржинальные направления.

## Матрица «город × услуга» (для кодинга)
Все **39 городов задействуются**. 20 регионализируемых услуг × 39 городов = **780 региональных страниц**. Полный список с URL — в `Матрица_город-услуга_Вагон-дом-2.0.xlsx` (лист «Список (плоский)» — по строке на страницу; лист «Матрица (услуга×город)» — сетка) и во вкладках самого файла структуры. URL-шаблон: `/{услуга-slug}-{город-slug}/` (напр. `/vagon-dom-stolovaya-tyumen/`); хаб города — `/vagon-doma-{город}/`. Разворачивать фазами по спросу/логистике, но охват — все города.

Статус: **рабочая структура сайта**; финальные правки — по вводным заказчика (города приоритетов, бренд/контакты, профиль).
